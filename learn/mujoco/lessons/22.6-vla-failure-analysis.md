## Core concept

When an autonomous policy fails an episode, recording a binary zero does not explain what went wrong. Did the vision encoder fail to detect the target object? Did language attention bind to the wrong entity? Did spatial planning misjudge clearances? Did the action head produce erratic commands? Or did physical contact slip at the surface?

In physical deployments, answering these questions requires laborious manual video inspection or privileged instrumentation. In MuJoCo, we can answer them with causal rigor through counterfactual intervention.

We replay each failed episode from its exact initial state, substituting ground-truth oracle signals for one pipeline stage at a time:

$$\mathrm{do}(\text{stage} = \text{oracle})$$

The earliest stage whose repair converts the failure into a success is identified as the causal failure mode. This attribution separates perceptual errors from language grounding and physical control.

## Visual intuition

The attribution procedure traverses a hierarchical tree of counterfactual interventions, ordered from low-level execution to high-level semantic reasoning:

1. Controller check: Replay the policy commands with ideal actuator tracking. If this succeeds, the failure was actuator lag or torque saturation.
2. Perception check: Replace image tokens with ground-truth object coordinates (the oracle vision model). If this succeeds, the failure was visual mislocalization or patch feature degradation.
3. Language grounding check: Replace the evaluation prompt with a canonical training template for the same task. If this succeeds, the failure was prompt interpretation or vocabulary mismatch.
4. Spatial reasoning check: Intervene on spatial binding by testing whether the policy directed its motion toward a distractor object rather than the target.
5. Action synthesis check: Allow the policy to execute until midway through the episode, then hand over control to the expert demonstrator. If the policy reached the vicinity of the object and the expert completes the task, the terminal failure was local contact manipulation. If the expert cannot recover, the policy drifted into an unrecoverable state.
6. Contact dynamics: If all prior stages were valid but the object escaped during contact, the failure is physical contact slip.

## Mathematics

### Causal intervention ordering

Let an episode rollout be parameterized by initial simulator state $s_0$, visual observation process $O$, language prompt $\ell$, spatial coordinate representation $Z$, policy action generation $\pi$, and physics transition dynamics $T$. The binary episode outcome is $Y \in \{0, 1\}$.

For a failed episode where $Y(s_0, O, \ell) = 0$, we apply a sequence of interventions:

$$\tau_k = \mathrm{do}(X_k = X_k^*)$$

where $X_k^*$ represents the privileged oracle implementation of stage $k$. The causal attribution index is defined as:

$$k^* = \arg\min_k \left\{ k \in \{1, \dots, K\} : Y(\tau_k) = 1 \right\}$$

Ordering matters. We test lower-level mechanical and perceptual sufficiency before attributing failure to high-level cognitive ambiguity. If a policy fails simply because its gripper slipped on an edge, diagnosing it as a language comprehension failure would be incorrect.

## Implementation

```io
INPUT: runs/vla/eval_patch.json (evaluation rollouts), trained MiniVLA weights, oracle MiniVLA
PROCESS: replay each failure under counterfactual stage repairs; record successful interventions
OUTPUT: runs/vla/diagnosis_patch.json and stage attribution breakdown table
```

```python file=examples/l22_6_failure_analysis.py
import argparse
import json
import multiprocessing
import os
from collections import Counter
from concurrent.futures import ProcessPoolExecutor
from pathlib import Path

import torch

from mjcourse.vla import diagnosis
from mjcourse.vla import evaluation as ev

RUNS = Path(__file__).resolve().parents[1] / "runs" / "vla"
_MODELS: dict = {}


def _load(path: str):
    if path not in _MODELS:
        _MODELS[path] = torch.load(path, weights_only=False)
    return _MODELS[path]


def job(args) -> dict:
    vision, record = args
    torch.set_num_threads(1)
    seed = record["model_seed"]
    model = _load(str(RUNS / f"minivla_{vision}_s{seed}_pos.pt"))
    oracle = _load(str(RUNS / f"minivla_oracle_s{seed}_pos.pt"))
    return {**diagnosis.diagnose(record, model, oracle), "condition": record["condition"], "seed": seed, "text": record["text"]}


FAST = os.environ.get("MJC_FAST") == "1"


def main() -> None:
    parser = argparse.ArgumentParser()
    parser.add_argument("--vision", default="patch", choices=["patch", "keypoint"])
    args = parser.parse_args()
    records = json.loads((RUNS / f"eval_{args.vision}.json").read_text())
    failures = [r for r in records if not r["success"]]
    if FAST:
        failures = failures[:4]
    workers = int(os.environ.get("SLURM_CPUS_PER_TASK", min(32, os.cpu_count() or 1)))
    with ProcessPoolExecutor(workers, mp_context=multiprocessing.get_context("spawn")) as pool:
        verdicts = list(pool.map(job, [(args.vision, r) for r in failures], chunksize=2))
    (RUNS / f"diagnosis_{args.vision}.json").write_text(json.dumps(verdicts))
    print(f"{len(failures)} failures of {len(records)} episodes (MiniVLA, {args.vision}), attributed to the first repaired stage")
    print(f"  {'condition':<16}{'failures':>9}" + "".join(f"{s:>20}" for s in diagnosis.STAGES))
    for c in ev.CONDITIONS:
        counts = Counter(v["stage"] for v in verdicts if v["condition"] == c)
        n = sum(counts.values())
        print(f"  {c:<16}{n:>9}" + "".join(f"{counts[s]:>20}" for s in diagnosis.STAGES))
    total = Counter(v["stage"] for v in verdicts)
    print(f"  {'all':<16}{len(verdicts):>9}" + "".join(f"{total[s]:>20}" for s in diagnosis.STAGES))
    print(f"wrote {RUNS / f'diagnosis_{args.vision}.json'}")


if __name__ == "__main__":
    main()
```

### Diagnostic insights

Language shifts are dominated by semantic grounding. In the synonym condition, 218 of 243 failures (90%) are cured immediately when replacing the synonym with the canonical prompt. The visual tokens and action head were entirely capable of executing the task; the failure lay strictly in the word embedding lookup.

Photometric shifts isolate perception. In the recoloured puck condition, 80% of failures are resolved by providing oracle object positions. The language grounding was correct, but visual attention tokens drifted between the target puck and distractors due to color similarity.

Cluttered scenes trigger spatial confusion. In the crowded condition, where pucks start within 6.5 to 10 cm of one another, 64% of failures are resolved by spatial trajectory intervention. The policy successfully navigates toward the cluster but collides with adjacent objects before reaching the target.

Embodiment mismatches expose control timeouts. In the slower pusher condition, 75% of failures are resolved by removing the actuator velocity throttle. The policy trajectory was geometrically sound, but execution speed fell below the required threshold for episode completion.

### Failure analysis on the 7-DOF Franka manipulator

On the 7-DOF Franka manipulator (`franka_vla.xml`), counterfactual replay isolates manipulation bottlenecks that do not exist on planar pushers:
- Grasp alignment slip: The gripper fingers contact the cube corners rather than opposite parallel faces, causing the cube to pivot out of the grip during lifting.
- Nullspace drift: Successive Cartesian delta commands pull the elbow joint toward its joint limit, causing singularity deceleration.
- Dual-view occlusion recovery: When an overhead view is blocked by arm self-occlusion during a descent, the wrist camera provides the necessary counterfactual recovery signal.

## Debugging

**Masking by broad interventions.** If an early stage in the diagnostic tree is too permissive (for instance, replacing actions with an optimal global planner too early), it will mask downstream failures. Ensure that each intervention repairs only its dedicated sub-problem.

**Non-deterministic replay drift.** Replaying a simulation episode requires setting the exact floating-point initial state: generalized coordinates, velocities, and numerical integrator state (`mjtState.mjSTATE_INTEGRATION`). If contact points are not preserved, chaotic divergences will invalidate the diagnosis.
