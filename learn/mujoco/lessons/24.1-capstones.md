## Core concept

The capstones are where the course stops giving answers. Each of the seven, A to G, asks for one artifact a robotics researcher builds with MuJoCo. Each comes with measurable acceptance criteria, a rubric shared by all seven, and a reporting standard. The final capstone is a research project of your own, run to the standard of Level 21. The course provides tools for all of them and checks for the parts that can be checked automatically. It provides **no reference solutions**: the capstones are specified, not built, in the sense of the [Projects](#/page/projects) page.

> [!established] What the course provides for the capstones
> - **Environments:** the environment base class and its checks (Level 12, `mjcourse.envs`).
> - **Control and manipulation:** controllers and manipulation routines (Levels 8 and 10, `mjcourse.control`).
> - **Perception:** cameras, rendering and ground truth (Levels 11, 15 and 21.5).
> - **Learning:** RL and imitation learning (Levels 13 and 14).
> - **Language:** language conditioning (Level 16).
> - **Transfer:** randomization, identification and transfer (Levels 17 to 19).
> - **Planning:** predictive sampling and world models (Lesson 21.4).
> - **Records:** protocols and run records (`mjcourse.experiment`, Lesson 21.1).
> - **Statistics:** `mjcourse.stats` (Lesson 21.2).
> - **Acceptance checks:** `mjcourse.capstone`.

## The acceptance checker

`python -m mjcourse.capstone module:Class --kwargs '{...}' --object BODY` runs, on any environment that follows the course's `MujocoEnv` conventions:

- Gymnasium's own `check_env`;
- the five checks of `mjcourse.envs.checks`: observations are copies, the time limit is reported as truncation, a seed reproduces an episode, every observation component is declared from a real sensor, and no privileged quantity (object velocity, mass, friction, contact stiffness) changes the observation;
- the compiled model's fingerprint, printed for the run record.

On the course's own push task with a privileged observation added, it prints:

```text
PASS  gymnasium check_env
PASS  observations are copies
PASS  time limit reported as truncation
PASS  reproducible with a seed
FAIL  observation sources are sensors: puck_velocity (simulator state)
FAIL  no privileged quantity leaks: object velocity
PASS  model fingerprint: fb3f9f19782505d054e4c0e5fcc2f64485e5dc041496de980d6ac2adad9efec8
```

and exits with status 1; without the added observation, every line passes (`tests/test_capstone.py`). The checker judges the instrument, not the research.

```python file=src/mjcourse/capstone.py
"""Acceptance checks for capstone environments (Lesson 24.1).

    python -m mjcourse.capstone mjcourse.envs.push:PushEnv --kwargs '{"action_mode": "ee_delta"}' --object puck

The environment must follow the course's MujocoEnv conventions (Level 12): `model`, `data`,
`max_episode_steps`, `observation_sources` and `_get_obs()`. The checks are Gymnasium's own checker and
the five checks of mjcourse.envs.checks; the compiled model's fingerprint is printed for the run record.
A capstone passes when every check passes; the checks do not judge the research, only the instrument.
"""

from __future__ import annotations

import argparse
import importlib
import json
import sys
import warnings

from gymnasium.utils.env_checker import check_env

from mjcourse.envs import checks
from mjcourse.experiment import model_fingerprint


def check(make_env, object_body: str | None = None, object_geom: str | None = None) -> dict:
    """Run every check; returns {name: (passed, detail)}."""
    results = {}
    try:
        with warnings.catch_warnings():
            warnings.simplefilter("ignore")
            check_env(make_env(), skip_render_check=True)
        results["gymnasium check_env"] = (True, "")
    except Exception as err:                                     # the checker raises on any violation
        results["gymnasium check_env"] = (False, str(err).splitlines()[0])
    results["observations are copies"] = (checks.observations_are_copies(make_env()), "")
    results["time limit reported as truncation"] = (checks.truncation_is_reported(make_env()), "")
    results["reproducible with a seed"] = (checks.reproducible(make_env), "")
    undeclared = checks.undeclared_sources(make_env())
    results["observation sources are sensors"] = (not undeclared, ", ".join(undeclared))
    if object_body:
        leaks = checks.perturbation_leaks(make_env(), body=object_body, geom=object_geom or object_body)
        results["no privileged quantity leaks"] = (not leaks, ", ".join(leaks))
    results["model fingerprint"] = (True, model_fingerprint(make_env().model))
    return results


def main(argv=None) -> int:
    parser = argparse.ArgumentParser(description=__doc__.splitlines()[0])
    parser.add_argument("target", help="module:Class of the environment")
    parser.add_argument("--kwargs", default="{}", help="constructor arguments as JSON")
    parser.add_argument("--object", default=None, help="body (and geom) of the manipulated object, for the leak check")
    args = parser.parse_args(argv)
    module, name = args.target.split(":")
    cls = getattr(importlib.import_module(module), name)
    kwargs = json.loads(args.kwargs)
    results = check(lambda: cls(**kwargs), args.object)
    for label, (ok, detail) in results.items():
        print(f"{'PASS' if ok else 'FAIL'}  {label}" + (f": {detail}" if detail else ""))
    return 0 if all(ok for ok, _ in results.values()) else 1


if __name__ == "__main__":
    sys.exit(main())
```
## Requirements common to every capstone

1. A protocol committed before the first evaluation run (Lesson 21.1), including the result that would falsify the main claim.
2. Every environment passes `python -m mjcourse.capstone`.
3. Training, development and held-out initial states on separate seeds; nothing chosen on held-out data.
4. Learned components trained with at least 5 seeds; results reported with intervals over seeds, and per task when there are several tasks (Lesson 21.2).
5. A run record (`mjcourse.experiment.run_record`) for every number in the report, with MuJoCo and library versions and model fingerprints.
6. A failure analysis: at least ten failed episodes from the held-out set, grouped by cause, with images or videos.
7. One command that regenerates each table and figure from the records.

## Rubric

Each row is judged as below, meeting or exceeding expectations; a capstone passes when it meets expectations in every row.

| Criterion | Meets expectations | Exceeds expectations |
|---|---|---|
| Validity of the instrument | checker passes; success defined in code and tested on a policy that nearly succeeds; no privileged leakage at evaluation | an independent check of the success definition (for example, rendered evidence for each success) |
| Methodology | protocol before results; held-out splits; ≥5 seeds; intervals over seeds | power analysis before running (Lesson 21.2); paired designs where possible |
| Results and analysis | every claim backed by a table or figure with its interval; failure analysis | an ablation that isolates the claimed factor; a reported negative result |
| Reproducibility | versions pinned; run records; one command per table | a clean machine reproduces the main table from the repository alone |
| Clarity | each metric and axis defined where it is used; figures with units | a reader can re-implement the evaluation from the report |

## Reporting standard

A report of at most eight pages: question and hypothesis; environment, written along the seven axes of Lesson 21.3; protocol; methods and baselines; results with intervals; failure analysis; limitations; reproduction instructions. Tables carry the number of seeds and episodes in their captions.

## The capstones

### A. A 7-DOF manipulation environment

**Objective.** A Gymnasium environment for a manipulation task of your choice on `arm7` (for example, opening a drawer, inserting a peg, or stacking), with torque, joint-delta and end-effector action modes (Level 12). **Builds on** Lessons 5.2, 8.3, 10.3 and 12.2. **Accept when** the checker passes in all three action modes; a scripted policy succeeds on at least 90% of 200 held-out starts (Wilson interval reported); and the documentation describes the task along the seven axes. **Common failures:** a success function that rewards near misses; observations read after `mj_step` without `mj_forward` (one step stale, Lesson 20.1); a task solvable by a constant action. **Extensions:** a second task sharing the scene; a randomized-object variant.

### B. A vision-based pick-and-place system

**Objective.** A pick-and-place policy that acts from rendered RGB or RGB-D images and proprioception only. **Builds on** Lessons 10.2, 11.2, 15.1 and 21.5. **Accept when** the policy receives no simulator state at evaluation (the checker's leak test passes on its observation); success with intervals over 5 seeds on held-out object positions; and the gap to the same policy with privileged object poses is reported, with a camera-pose-shift evaluation. **Common failures:** the object pose reaching the policy through an auxiliary input; evaluation on training positions; a single camera pose. **Extensions:** depth against RGB at equal data; distractor objects.

### C. A language-conditioned manipulation benchmark

**Objective.** A benchmark of instructions over a manipulation scene, with training and held-out instructions (paraphrases and new compositions) and held-out object placements. **Builds on** Lessons 16.1 and 21.3. **Accept when** at least ten instruction templates exist with a documented held-out split; a language-blind baseline (the same policy given an empty instruction) and chance level are reported; and results are separated by generalization axis (object, spatial, instruction). **Common failures:** instructions that a scene alone determines; paraphrases seen in training; per-episode aggregation over unequal tasks. **Extensions:** a VLA baseline evaluated on it with Capstone E's evaluator.

### D. A bimanual manipulation environment

**Objective.** An environment that needs both arms, such as a handover or a two-handed lift, on the course's bimanual scene. **Builds on** Lessons 5.4, 8.3 and 10.1. **Accept when** the checker passes; a scripted two-arm policy succeeds on at least 80% of held-out starts; and a one-arm ablation shows that the task needs both arms. **Common failures:** a task one arm can do; self-collision between the arms ignored in the success definition. **Extensions:** asymmetric roles; a learned policy.

### E. A VLA evaluation environment

**Objective.** An evaluator that takes any policy mapping (images, instruction, proprioception) to actions and reports success along generalization axes. **Builds on** Lessons 16.1, 21.2, 21.3 and 21.5. **Accept when** the evaluator passes only declared sensors to the policy (verified with the checker); a scripted oracle and a random policy bracket the reported range; results come per axis with intervals; and the evaluator writes a run record per evaluation. **Common failures:** the policy reading simulator state through the environment object; axes that change several factors at once. **Extensions:** an open-weight VLA evaluated on it, with its training distribution documented.

### F. A world-model-based manipulation agent

**Objective.** A planner that uses a learned dynamics model for a manipulation task, such as pushing. **Builds on** Lesson 21.4. **Accept when** the model's fidelity, action-conditioned accuracy and the planner's success are reported separately; the same planner with MuJoCo as its model is the reference; and the training data's coverage of the states the planner visits is measured. **Common failures:** one-step error reported as model quality; exploration data that never visits the task's states. **Extensions:** a latent model learned from images.

### G. A sim-to-real-ready environment with domain randomization

**Objective.** An environment whose parameters are identified from data and whose randomization ranges come from that identification, with latency and actuator models. **Builds on** Lessons 17.1, 18.1, 18.2 and 19.1. **Accept when** identified parameters carry intervals; randomization ranges are justified by them; a held-out "real" variant with hidden parameters is evaluated by a transfer experiment designed to fail informatively, as in Lesson 19.1; and performance is plotted against the size of the mismatch. **Common failures:** randomizing parameters the controller is insensitive to; delays shorter than the actuator's history (`nsample`) can hold. **Extensions:** hardware, if available.

### The final capstone

**Objective.** A research question of your own, studied with MuJoCo to the standard of Level 21. **Accept when** Checkpoint 21's protocol was committed before the runs, the study meets every common requirement, an ablation isolates the factor the claim depends on, and the report includes the result that would have falsified the hypothesis and whether it occurred. The final examination is on the [Final expert exam](#/page/final-exam) page.
